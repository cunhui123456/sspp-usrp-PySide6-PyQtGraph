# 温压固件准备与实时采集

软件内选择“温度”或“压力”只决定本次实验需要的程序和解析协议，不会自动改变 Nano 上运行的代码。2026-09-07 的温度实验结束后曾恢复原压力应用；再次做温度实验需重新烧录温度固件，或验证板上当前已经输出温度协议。

## 操作顺序

1. 用数据线连接传感器 Nano，关闭 Arduino IDE 串口监视器及其他占用工具。通过桌面“多传感器实验台.command”打开软件。
2. 点击全局“初始化实验台”，选择 Arduino USB 串口并检查。不连接 USRP 时可取消 B210 勾选。列表仅保留 USB 候选；端口名称不代表已经认定板卡身份。
3. 进入“温压采集”，选择实验模式，核对 **Nano / ATmega328P / Old Bootloader** 与接线并勾选确认。压力原程序为 **P2 / S3 → A2**；温度检查 v1 为 **P5 / S6、P6 / S7 → A1**，两路顺序采样。实际样品位置仍按接线记录填写。
4. 点击 **“烧录并验证”**，确认目标端口、板型和固件。程序检查本机工具与固件哈希，读取芯片签名并保存完整 Flash 备份，然后写入应用并校验，最后验证至少三个连续且 MCU 时间递增的数据帧。进度同时显示在右侧与启动器终端。
5. 如果板上已经运行所选程序，可以使用 **“验证已有固件”**。它不烧录，只验证数据协议，不鉴定板上程序二进制身份。协议不匹配时会提示切换模式或烧录，不自动修改选择。
6. 验证通过后填写样品名称、实际通道和说明，点击 **“开始记录”**。右侧显示实际收到的电压／ADC；点击“停止并保存”封存数据，随后在“研究分析”查看或标定。

全局“端口已检查”只说明串口可以打开；“数据已验证”才允许正式记录。更换端口、实验模式或板型、重新检查 Arduino、采集失败都会撤销准备状态。仅切换温度／压力模式时保留 USB 端口检查，不必再次全局初始化；单独检查 B210 也不清除 Arduino 的固件验证。准备、采集或保存期间不能切换实验、初始化设备或启动 RF；可以停止当前操作。Flash 写入与校验期间请求取消会等待该步骤完成，请保持连接，结束后不会自动开始采集。

## 固件与运行工具

两种应用采用先前实机验证的 HEX，配套源码和来源 SHA-256 位于 [firmware/temperature_pressure](../firmware/temperature_pressure/README.md)。本次不改算法，也不把旧固件重新编译为未经验证的版本。上传速率为 **57600**，采集串口为 **9600**。

烧录优先复用 Arduino IDE 开发板工具包自带的 `avrdude` 及配置。先用帮助命令确认能运行；若捆绑的 Intel 版本报架构不兼容，再尝试已安装的原生工具，例如 `/opt/homebrew/bin/avrdude`。工作台不重新实现上传协议，只负责调用工具、检查与记录证据。软件不会自动安装依赖、写 EEPROM、改熔丝或写 bootloader。仅支持该已验证 Nano 板型；USB 桥的 VID/PID 不是 MCU 身份证明，烧录前还会检查 ATmega328P 签名 `1e950f`。

## 数据与故障证据

- `Data/device_preparations/<时间>/` 保存每次准备日志、签名、烧录前完整 Flash、待写入应用 HEX、验证串口原始字节和来源哈希。备份是恢复当前应用所需证据，不是清理对象；完整 Flash 含 bootloader，不能直接当作普通应用回写。结束实验不会自动恢复旧固件。
- `Data/temperature_pressure_runs/<时间>/` 保存正式实验原始字节、样本 CSV、事件、manifest 与对应准备记录。验证阶段的样本不混入正式曲线。
- 采集开始后 10 秒仍无有效样本会结束本次接收并保留证据。**0 原始字节**提示端口、数据线、供电或程序无输出；**有字节但无有效样本**提示协议或固件问题。收到样本后停更超过 3 秒会提示停更，曲线保留最后实收值，不补点或伪造实时数据。
- “样品名称未填写”等旧错误会在成功开始准备或采集后清除。

这些检查证明工具流程和数据格式，不等于温度／压力标定，也不证明两种模式同时采样。历史实验及数据保持原样。
