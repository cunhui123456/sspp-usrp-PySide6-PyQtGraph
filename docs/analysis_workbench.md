# 采集后直接分析与温压串口采集

继续使用根目录 `run_desktop.command`。新增「温压采集」和「研究分析与模型」页面；采集结束后直接选择本项目的数据，不需要导出 ZIP 或搬移文件。

1. 材料／手指沿用现有采集流程。温压在新增页面选择真实板上协议、串口、样品与通道，开始接收并停止保存。
2. 在「研究分析与模型」选择材料、手指或温压任务，勾选已完成记录，先查看响应曲线。
3. 有真实标签／参考值后，在页面填写材料类别与独立验证角色，或尺量／参考仪器区间，保存草稿并训练／标定。
4. 查看验证结果；通过后选择保存的版本模型预测或回放。数据不足、质量不合格、参数不一致或范围外时查看具体原因。

数据格式以本实验平台为准。原始 SSPP 数据留在 `Data/runs`、`Data/phase_runs`；新温压留在 `Data/temperature_pressure_runs`。派生结果与模型另存同级 `rf-analysis/analysis_runs`，不改原始数据；旧 rf-analysis 数据仅历史留存。

首版没有数据库依赖。配置通过现有 `.env` 的 `SSPP_ANALYSIS_PROJECT`／`SSPP_ANALYSIS_PYTHON` 指定现有分析项目和 Python，默认当前同级目录与已有 `rf-analysis` 环境，原 `.env` 保留。温压接收不依赖新增包，不烧录、不发控制命令；当前只支持 Mac 的 `/dev/cu.*` 及两种已有 Arduino 文本协议。

手指模型仅同一次 run；温压未标定值保持 ADC／电压。温压区间使用 MCU elapsed 时间与复位段号，主机接收时间不冒充采样时间。材料分类最低需两类、每类独立训练与验证 run；不能拆同一 run 的重复轮次充当独立实验。

详细算法、记录结构、最低数据条件与数据库分工见相邻分析项目的 [完整联动说明](../../rf-analysis/docs/DESKTOP_WORKBENCH.md)。本项目已有「手指标定与验证」和离线诊断入口继续可用，新工作台统一调用分析平台。
