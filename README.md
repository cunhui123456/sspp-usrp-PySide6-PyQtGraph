# 多传感器实验台 · PySide6 / PyQtGraph

用于 USRP 射频和 Arduino 温度／压力研究的本机桌面软件：顶部全局导航提供 **材料扫频、手指位移、液体温度影响、温压采集** 四类实验。左侧显示当前实验的专属参数，右侧用于实时观察、已保存记录和分析；采集后可在同一软件内直接调用 `rf-analysis` 分析、训练与标定。

操作步骤见 **[采集后直接分析与温压采集](docs/analysis_workbench.md)**、**[实验工作流](docs/experiment_workflows.md)**；多条记录的筛选、叠加与差值见 **[结果比较](docs/results_comparison.md)**；原设计基线见 **[项目设计说明](docs/design.md)**。原项目 `sspp-usrp` 保留；本项目不运行 FastAPI 或 HTTP 服务。

## 采集后直接分析（2026-10-13）

“温压采集”通过顶部实验导航进入，USB 串口、实验模式、固件准备、样品及开始记录操作位于左侧，右侧显示实时曲线和事件。先显式烧录已验证固件或验证板上现有输出，再接收两种已验证过的 Arduino 文本协议，后台保存原始字节、CSV、事件与停止证据。顶部“研究分析与模型”入口直接选择本项目 `Data/` 的完成记录，支持响应曲线、材料分类训练／预测、同 run 手指距离／位移标定与温压参考值拟合。材料标签、参考区间与独立验证角色在页面填写，草稿、分析结果和模型按版本保存于相邻 `rf-analysis/analysis_runs/`。

数据格式以本实验平台为准，原始文件无需迁移、复制或转换为 rf-analysis 旧 Manifest。旧平台记录留存，首版不依赖 PostgreSQL。当前没有训练／标定数据集；软件流程可用不等于已获得真实分类准确率或物理量精度。详细条件见 [联动说明](docs/analysis_workbench.md)。

## 启动

项目当前目录为 `multisensor-workbench`，桌面入口为 **“多传感器实验台.command”**。唯一面向日常使用的启动器是项目根目录 **[run_desktop.command](run_desktop.command)**。在 Finder 双击，或在项目目录执行：

```sh
./run_desktop.command
```

继续使用现有 **Conda `rf-gnuradio`**，不建立第二个环境。启动器使用该环境的绝对 Python 路径。打开窗口、读取历史和检查参数均不连接 USRP；开始采集前仍需确认本次设备、接线和实验参数。

桌面增量依赖为 `requirements-desktop.txt`。仅环境缺包时，在既有环境中安装：

```sh
conda activate rf-gnuradio
python -m pip install -r requirements-desktop.txt
```

不要用 pip 重装另一套 UHD，不替换既有 FPGA 镜像，不修改全局 `.zshrc`。此前验证环境为 Python 3.14.6、PySide6/Qt 6.12.0、PyQtGraph 0.14.0、GNU Radio 3.10.12.0；具体测试和安装证据见 [桌面验收记录](docs/acceptance_desktop.md)。

## 两类设备独立初始化

启动默认进入第一项 **“材料扫频”**，只读取界面、本地配置与历史。点击导航最左侧 **“初始化实验台”**，弹窗同时提供 **USRP B210** 和 **Arduino 温压串口** 两组设置：选择自有／老师 B210，以及 Arduino USB 串口，勾选本次要检查的设备后确认。打开或取消弹窗均不连接设备、不改变原设置。

两类设备分别保存就绪结果：**缺少 USRP 时仍可做 Arduino 温压实验；缺少 Arduino 时仍可做射频实验**。不可用的一方在状态区显示原因，详细诊断写入终端和日志，不作为整个试验台的失败。全部未就绪时仍能设置参数、查看历史与分析。开始按钮只检查当前实验需要的设备；切换实验不会撤销另一方的就绪状态。修改 B210 配置只撤销 USRP 就绪，修改串口只撤销 Arduino 端口检查；切换温压实验模式只撤销固件验证，USB 端口检查保持。

初始化先检查所选串口，再检查所选 B210，均在后台独立子进程执行。Arduino 最长30秒，B210 最长120秒；等待驱动时终端每10秒显示进度。顶部“取消初始化”中止尚未完成的检查，**已经检查成功的一方保持就绪**。未勾选的一方本次跳过，不自动连接；既有且配置不变的就绪状态保留。

B210 检查 FPGA 文件、设备身份及通道，不建立 RF 数据流、不发射。UHD 可能载入运行固件和 FPGA。全局初始化仅按9600波特率独占打开 Arduino USB 串口并关闭，不读取实验数据、不发控制命令、不烧录；打开可能引起 Nano 复位。沿用此前已验证的压力和双通道温度协议，初始化检查仅确认当前连接，不重新标定传感器。端口检查成功后释放设备，温压实验还需完成左侧“烧录并验证”或“验证已有固件”，至少收到三个匹配且时间递增的完整帧才允许开始记录。准备与采集均需确认当前板卡和接线。详见[温压固件准备流程](docs/temperature_firmware_workflow.md)。

**启动器终端实时显示过程**，每个设备的每次检查保存在 `.cache/initialization_logs/`，状态悬浮提示提供日志路径。失败、取消、超时及退出码均保留；设备标识沿用脱敏。日志文件不可写时提示并继续检查。重新打开软件从未初始化开始，设备选项不会改写 `.env`。

## 全局导航与参数草稿

先在窗口顶部选择实验，再填写左侧参数。右侧只展示与当前实验相关的工作页：

| 顶部实验 | 左侧专属设置 | 右侧工作内容 |
|---|---|---|
| 材料扫频 | 材料／条件名称、扫频与高级采集参数 | 实时扫频、实验档案与回放、曲线诊断、研究分析 |
| 手指位移 | 尺量参考、误差门槛、窗口时长、引导／自由方式与距离计划，以及固定载频参数 | 连续幅相、现场采点与动作、区间标注、标定与验证报告 |
| 液体温度影响 | 样品、容器、液量、参考温度、位置与重复编号，以及本次扫频／固定载频参数 | 实时 RF、温度记录与比较、稳定区间和分析报告 |
| 温压采集 | USB 串口、板型、实验模式、烧录／数据验证、样品与通道、开始记录 | 实时电压／ADC 曲线、采集事件、研究分析 |

B210 全局选择在当前窗口内共用；重新打开时按本机默认配置选择，不改写 `.env`。各实验的待采集参数草稿在**当前窗口内分别保留**，切换后恢复对应设置，其他实验的草稿不会被当前实验参数复位覆盖。切换实验会清除本次接线确认；再次采集前须重新检查并确认。切换不会自动开始 RF 或打开串口。

初始化、采集、参数检查、停止保存及相关结果处理期间不能切换实验。**“停止并保存”固定在顶端**，采集中即使查看右侧档案或分析页也能使用；无活动采集时按钮禁用。停止请求后仍须等待保存及停止证据，不能把按钮点击当作收发已经结束。

顶部“全部实验档案”可跨实验类型查找已有 RF 记录，解除“仅当前实验”筛选；它不改变当前实验的采集设置。温压串口历史记录仍从“研究分析与模型”的数据源列表进入，本轮没有改变历史数据后端。档案、图表和分析页的切换不会启动硬件。

液体温度实验应先在左侧填写条件并点“应用条件到采集参数”，再检查本次 RF 参数、重新勾选接线确认并开始采集；只选择顶部实验或修改条件表单不会自动应用或开始收发。温压实验使用左侧自己的串口设置和确认，不沿用 RF 接线确认。

## 选择实验

| 研究任务 | 流程 | 结果边界 |
|---|---|---|
| 比较材料或条件的扫频响应 | 填写材料／条件名称，固定样品和线缆，运行逐点扫频 | 频率—幅度、各轮测量和重复性；换材料后另起一次实验，不自动识别材料 |
| 用规定距离逐步标定手指 | 固定载频，建立静止参考，按引导输入尺子距离并采集稳定窗口 | 至少 3 个标定距离、2 个独立验证距离；通过质量和误差门槛才启用毫米估算 |
| 自由探索手指动作 | 连续记录幅相与人工动作；在保存记录中选择静止区间并填入当时的尺子真值 | 同一算法、同一质量门槛；不能从曲线反推“真实距离”或把同一静止段拆作独立验证 |
| 液体温度对扫频和位移相位的影响 | 顶部选“液体温度影响”，在左侧登记并应用条件，再检查／确认／开始；停止后补温度和稳定区间 | 温度扫频叠加/差值、各温度平台相位—位移斜率、同run固定位置漂移；跨run仅比较各自归零的响应 |
| 接收 Arduino 温压原始读数 | 顶部选“温压采集”，初始化 USB 串口，烧录或验证对应固件后开始记录 | 原始字节、ADC／名义电压、事件与时间；物理量须另外用参考仪表标定 |

液体温度实验完整操作、升降温与重复设计、报告位置及解释限制见 [液体温度影响实验](docs/liquid_temperature_experiment.md)。实际温度和距离由操作者参考仪表记录；程序不控制加热、丝杠或温度计，不自动开始下一温度。

距离是操作者定义几何基准后量得的**传感器到手指距离**。位移 = 当前距离 − 初始尺量距离，正值表示远离。毫米值来自同一次连续采集内的单调相位经验曲线，不由波长直接换算，不跨实验复用相位基线。

默认允许误差 **2 mm 是可调整的验证门槛，不是已经测得的精度**。误差针对独立静止区间的相位中位数；不代表所有瞬时读数或新会话都达到该精度。标定失败、数据质量不足、超出标定范围或停止实时采集时，估算显示不可用原因。

## 保存、回看与导出

停止后等待保存和 RF 停止证据；`stop_unconfirmed` 不能视为已确认停止。历史记录可查看幅相／扫频、只读回放、完整诊断，手指记录还可重新选择区间进行离线研究分析。

停止后点“本次结果与导出 →”定位当前记录；“打包导出实验…”让你选择 ZIP 保存位置，收集参数、结果数据、重要图表以及已有手指标注／标定／独立验证报告，并生成来源与文件哈希索引。**原始 IQ 默认不选**；需要复算时勾选包含原始 IQ，包体可能较大。导出不能自动终止正在运行的实验，须先结束采集并确认保存。

原始 IQ、帧证据、manifest 和老师冻结代码保持不变。手指研究分析按版本写入 `finger_research/`，保留所用数据、标注、代码来源与误差结果；不覆盖旧分析。

## 已保存实验的筛选与比较

“实验档案与回放”默认勾选“仅当前实验”；顶部“全部实验档案”解除该范围限制。结果列表可再按类型、状态和关键词筛选；勾选 2–8 条同类型完成记录生成比较，扫频默认最早记录为差值参考并可切换。扫频呈现各 run 的均值 ± 样本标准差；参数完整且一致时，只在全部所选记录共同的 UHD TX／RX 载频回读与基带单音组合上计算“目标 − 参考”幅度差，不插值。参数缺失或不一致时保留叠加，说明差值不可用原因。

连续幅相按各自基线结束时刻对齐，展示每次实验相对自身基线的响应，不做跨 run 相位相减，不复用毫米模型。老师原版历史记录单独分类。对比结果可另存 ZIP，包含报告、参数、CSV、PNG／PDF、选用源结果和哈希；该包不含原始 IQ，单次实验导出保持原流程。细节见 [结果比较说明](docs/results_comparison.md)。

## 实时显示与数据完整性

- 完整 IQ、逐窗幅相和采集质量证据按原采集协议保存。
- `TRACE` 默认每 100 ms 批量发布，GUI 默认每 100 ms 更新；`PREVIEW` 默认每 250 ms 发布最新真实 RX 诊断窗口。
- 显示拥塞可以跳过显示批次，必须可见并计数；原始处理队列满会失败停止，不静默丢原始数据。
- 连续幅相按设备实际主时钟整数计数检查 RX 连续性。拒绝帧信息保存在 `rx_timestamp_failure.json`，历史详情显示实际错误。
- 历史 phase 回放按保存的样点时间播放；旧 sweep CSV 无逐点真实时间，按每点 1 秒演示。
- 配置周期不等于已测得的硬件到屏幕延迟；软件测试不代替真实动作和毫米精度实验。

## 开发验证与科研边界

以下是开发诊断命令，不是日常启动流程：

```sh
conda activate rf-gnuradio
QT_QPA_PLATFORM=offscreen PYQTGRAPH_QT_LIB=PySide6 MPLBACKEND=Agg python -B -m pytest -q
python -B run_desktop.py --check
```

`--check` 只检查依赖和本地记录，不打开硬件。2026-10-09 保存记录证明一次空载静态连续幅相与主动停止初验；不自动证明新版手指标定、桌面扫频或实际毫米精度通过。最新范围以 [验收记录](docs/acceptance_desktop.md) 为准。

数字幅值／频谱为 dBFS 估计，不是标定 dBm 或 S21。尺量经验曲线不等于通用电磁测距模型，不自动产生材料分类、生命体征或 AI 结论。新增分析在独立模块消费只读数据，重计算不进入 RX 保存或 Qt 主线程。
